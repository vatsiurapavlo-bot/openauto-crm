# Правила роботи Claude з OpenAuto CRM

Цей файл читає Claude на початку кожної сесії роботи з кодом. Власник не програміст: зміни мають бути
безпечними, перевіреними й пояснені простими словами (українською). Інтерфейс CRM — польською.

## Публікація змін

1. **Ніколи не пушити напряму в `main`.** Кожна зміна — окрема гілка (`zmiana/<коротка-назва>`) і Pull Request.
2. Перед PR запустити локально: `npm run build`, `npm run typecheck`, `npm test` (потрібен PostgreSQL —
   `TEST_ADMIN_DATABASE_URL`). У PR описати українською: що змінено, як перевірено, скріншоти інтерфейсу.
3. Злиття (Merge) робить **лише власник**. Railway розгортає `main` тільки після успішних тестів GitHub
   Actions («Wait for CI»).
4. Не змінювати змінні Railway, не підключатися до продакшн-бази й не виконувати дії з реальними даними
   без прямого прохання власника в чаті.

## База даних

- Міграції лише **додавати** (`db/migrations/NNNN_*.sql`), ніколи не змінювати вже застосовані — перевіряється
  контрольна сума.
- Міграції мають бути **сумісні з попередньою версією коду** (лише додавання колонок/таблиць; видалення —
  окремим етапом пізніше). Причина: відкат у Railway (Rollback) повертає код, але не базу.
- Права доступу — у трьох місцях: перевірка на сервері (`requirePerm`), RLS-політики та тригери в БД,
  приховування в інтерфейсі. Нові таблиці з бізнес-даними — завжди з `workspace_id` і RLS.
- Гроші — `NUMERIC(14,2)` у БД, `src/shared/money.ts` у коді. Ніяких float.

## Архітектура (не переписувати без потреби)

React SPA (`src/client`) + Node.js-сервер без фреймворку (`src/server`) + PostgreSQL. Опис —
`docs/ARCHITECTURE.md`, стан етапів — `docs/ETAPY.md`, розгортання — `docs/RAILWAY.md`.

## Безпека

- Секрети лише в змінних Railway; ніколи в коді, логах, PR чи чаті.
- `OPENAUTO_MASTER_KEY` шифрує резервні копії і токен Google Drive. Зміна ключа = старі копії не відкриються.
- Перед зміною авторизації, сесій, RLS чи резервних копій — попросити окремий незалежний огляд безпеки.
